# 许可与数据

这里说明包里每一类东西的许可、依赖的第三方组件，以及 SN-GSR 数据带来的限制。内容依据 gbf 仓库的登记表（`registries/data.toml`、`registries/models.toml`，2026-10-21 核实）、设计记录 ADR 0001 和 0002，以及 [provenance-gsr.json](../pipeline/gsr/provenance-gsr.json) 里的许可记录。**这些是项目的工程判断，不是法律意见。**

## 1. 包里的东西

| 内容 | 许可 / 状态 | 说明 |
|---|---|---|
| 实验台代码（`method/`、`evidence/` 里的脚本）、`relocate.py` | 随 gbf 仓库：MIT | 只导入 gbf 的基础模块，不包含第三方代码 |
| 文档 | 随 gbf 仓库的文档约定 | |
| `pipeline/` 里的脚本 | 自己写的；但只能在第三方环境里运行（见下） | `run_tracklab*.py`、`ball_detect.py`、`export_*.py` 会导入 tracklab、sn-gamestate、ultralytics 等 |
| `pipeline/patches/sn-gamestate-local*.patch` | 对 GPL-3.0 代码的修改，按 GPL-3.0 | 只有补丁，不含 sn-gamestate 的源码 |
| `pipeline/patches/prtreid-local.patch`、`bpbreid-local.patch` | 对 Hippocratic License 3.0 代码的修改 | 各一处，很小；使用这两个库的人要自己接受它们的许可 |
| 拟合参数（各 `params*.json`、`final_params.json`、`loco_params.json`、`cutlink_params.json`） | 继承 SN-GSR 的使用限制（见第 3 节） | 研究用途 |
| 方法文件和打分文件（`METHOD_*.json`、`OUT_*.json`） | SN-GSR 片段上的跟踪结果的衍生物 | 只有跟踪器的片段编号和计数，没有像素，没有标注内容 |
| `pipeline/selection.json` | 元数据 | 片段名单、压缩包的 sha256 |

需要主会话或负责人决定的一点：`pipeline/` 的脚本会导入 GPL 和 AGPL 的包。目前按“自己写的脚本，在第三方环境里独立运行”处理；如果要更保守，可以把 `pipeline/` 整个标成 GPL-3.0-only。

## 2. 依赖的第三方组件（都不在包里）

| 组件 | 许可 | 在这里怎么用 |
|---|---|---|
| sn-gamestate（SoccerNet） | GPL-3.0-only；内含 NBJW / PnLCalib（GPL-2.0-only）和没有许可声明的 sn-calibration 代码 | 输入流程的跟踪步骤。作为独立进程运行，只通过文件交换结果 |
| tracklab 1.3.24 | MIT 和 GPL-3.0-only（内含的跟踪器） | `run_tracklab*.py` 运行时导入；`exact_reader.py` 替换它的读帧器 |
| prtreid、bpbreid | Hippocratic License 3.0（有用途限制，不是 OSI 许可，和 GPL 不兼容） | 外观向量和跟踪 |
| NBJW（No Bells Just Whistles） | GPL-2.0-only；权重许可未声明 | 球场关键点和相机标定 |
| ultralytics（YOLO11m） | AGPL-3.0 | 找人、找球 |
| EasyOCR | Apache-2.0（依赖 python-bidi 是 LGPL-3.0-or-later；权重许可未声明） | 原来的跟踪设置里读球衣号；负责人的设置里不用 |
| mmocr | Apache-2.0 | 已被补丁从依赖里去掉 |
| 模型权重 | Zenodo 上标 CC-BY-4.0（记录 12626395、10653453、10604211）；项目登记表把 prtreid 权重按 HL3 对待；`yolo11m.pt` 是 Ultralytics 的发布文件（AGPL） | 由 `fetch_weights.sh` 从原始来源下载，校验值在 `provenance-gsr.json` |

GPL-2.0-only 和 GPL-3.0 互不兼容，这是输入流程必须作为独立进程运行、不能被 gbf 核心导入的原因。

## 3. SN-GSR-2025 数据

- 数据集在 Hugging Face 上标的是 GPL-3.0。画面来自 2019 年瑞士超级联赛的转播，版权属于联赛或转播方；GPL 这个标签不等于对画面的授权。
- 项目登记表里的规则：可以本地处理、评估、拟合、**发布汇总数字**；**不可提交进仓库**；只发数字，不发画面。
- 所以这个包里**没有**：画面、视频、运行数据、标注文件、逐条的明细表。只有汇总数字、代码、参数和文档。详见 [文件清单.md](文件清单.md) 第 6 节。
- 各 `README.md` 里有少量句子提到具体的标注编号（说明哪几次回来被认错）。如果要求更严，可以删掉这些句子，清单在 [packaging-changes.json](packaging-changes.json) 的 `kept_but_note`。
- 看片数据（`viewer_data.py` 的输出）里有标注框，只能留在本机；`serve_runs.py` 只绑定 127.0.0.1。

## 4. 拟合参数的使用限制

按 ADR 0002 第 3 条：拟合出来的参数继承数据来源的限制；商业构建只接受“每个数据来源都允许商业使用”的参数，SN-GSR 不在这个范围里。

这个包里所有拟合参数都只用了 SN-GSR 训练集的 13 段片段：

| 文件 | 内容 |
|---|---|
| `method/reid_lab/work/m_cuts/{final_params,loco_params,cutlink_params}.json`、`loco_models.json` | 切开模型 |
| `method/reid_lab/work/m_space/{params_all13,params_loco}.json`、`params_cache/excl_*.json` | 位置模型 |
| `method/reid_lab/work/fuse_r1/params_loco.json` | 合成的配对模型和各档门槛 |
| `results/leadcfg-settings/refit_R/` 下的同名文件 | 在负责人设置的结果上重新拟合的一套 |
| `evidence/` 下各轮的参数文件 | 历史 |

标记：**在 SN-GSR-2025 的 13 段开发片段上拟合；研究用途；未经复核不用于商业构建。**

产品版 `gbf.relink` 带的冻结参数就是上面 `all13` 那一套，同样受这条限制。它们目前没有登记在 `registries/metrics.toml` 里（那张表只登记“指标”的拟合参数）；要不要登记，由负责人决定。

外观向量来自 PRTReid（HL3）在 YOLO（AGPL）检测结果上的输出；用到外观向量的运行结果带着这两个限制标签。

## 5. 使用这个包时

- 只读文档和数字：没有额外限制。
- 运行实验台：需要自己取得 SN-GSR 数据并遵守上面的规则。
- 运行输入流程：需要自己安装第三方组件并接受它们各自的许可。
- 把参数或方法用到产品里：先看第 4 节。
