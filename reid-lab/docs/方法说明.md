# 方法说明

本文说明认人方法 `fuse_r1` 是什么、怎么做、哪些数是拟合出来的、成绩是按什么规矩算的，以及它和 gbf 里的 `gbf.relink` 是什么关系。数字的出处见 [结果汇总.md](结果汇总.md)，要打的折扣见 [局限.md](局限.md)。

## 1. 要解决的问题

跟踪器给画面里每个人一个编号。球员走出画面再回来时，跟踪器经常给他一个新编号，有时还把别人的旧编号给他。认人方法要做的是：把同一个人前后的几段重新接到一起，同时尽量不把两个人接成一个。

几个词：

| 词 | 意思 |
|---|---|
| 片段（piece） | 跟踪结果里同一个编号的一段框。gbf 已经在“出画面再回来”的地方把插件的轨迹切开，所以一条插件轨迹可能对应几个片段。 |
| 回来（return） | 标注里的一名球员或守门员，至少 10 帧不在画面里，而且离开前或回来后的框贴着画面边缘。13 段里一共 167 次。 |
| 认对（right） | 回来后的编号和离开前是同一个身份。 |
| 认成别人（wrong） | 回来后的编号之前主要属于另一个人。 |
| 当成新人（lost） | 回来后是一个新身份。没接上，但也没认错。 |
| 没检测到（undetected） | 回来那一刻跟踪器没找到这个人，哪种方法都没法打分，不计入成绩。 |
| 拼接（link） | 方法把两个片段判成同一个人。 |
| 混进别人的框（impure rows） | 一个身份下面，有多少框其实属于另一个人。防止方法靠“到处乱接”换成绩。 |

打分规则写在 [score.py](../method/reid_lab/score.py) 开头，和输入流程里的检查脚本 [gsr_reentry_eval.py](../pipeline/analysis/gsr_reentry_eval.py) 完全一致，由 [check_score.py](../method/reid_lab/check_score.py) 在 13 段上逐段核对。

## 2. 方法用到的输入

每段片段读这些文件（都不含标注），由 [data.py](../method/reid_lab/data.py) 统一读取：

- `gbf/refine/tracks.parquet`：每个框一行，720p 坐标，有片段编号、插件编号、队别、角色、球场坐标。
- `gbf/refine/calib.parquet`：每帧的相机标定。
- `reid-embeddings.npz`：每个框的外观向量（PRTReid，256 维）。
- `gbf/refine/refine.json`、`appearance-match.json`：gbf 的记录和上一次外观试验的候选对（只给对照做法用）。

这些文件怎么生成，见 [运行手册.md](运行手册.md) 第 2 节。

## 3. 方法的五步

应用部分的代码是 [fuse_r1/method.py](../method/reid_lab/work/fuse_r1/method.py)，它不读任何标注。

1. **先切开。** 插件的一条轨迹有时中途从一个人跳到另一个人身上。在片段内部找这种地方，判断“前后是不是两个人”的概率达到 0.7 就切开。只切不拼时，认成别人从 4 次降到 0 次，混进别人的框从 2.61% 降到 1.00%。代码在 [m_cuts](../method/reid_lab/work/m_cuts/)。
2. **分长短。** 切开后，至少 5 个框的片段叫“可靠片段”，更短的叫“碎片”。
3. **算证据。** 对每一对可靠片段算三样：
   - 外观：每个片段一个外观原型，先减掉所在队伍的平均外观，再做白化，然后比相似度。同队球员穿一样的球衣，减掉队伍平均后剩下的才是区分个人的部分。代码在 [m_appear](../method/reid_lab/work/m_appear/)。
   - 位置：后一段开始的地方，是不是前一段那个人在这段时间里跑得到、而且合理的地方。只在可靠片段之间算，这样一个小碎片不会把两段长片段之间的位置证据“吸走”。代码在 [m_space](../method/reid_lab/work/m_space/)。
   - 插件自己有没有把这两段接起来。在可靠片段上这一项拟合出的权重接近 0，实际不起作用。
4. **拼接。** 两组可靠片段满足下面全部条件才接到一起，最像的先接：
   - 同一队，而且从没在同一帧里同时出现；
   - 外观相似度至少 0.3；
   - 互为最佳搭档；
   - “外观 + 位置加分”要比“谁都不是”（0.5）高出一个门槛，也要比任何和对方同时在场的竞争者高出这个门槛，两边都要满足。
5. **挂碎片（只在多认档做）。** 一个碎片最多挂到一组身上，规则和第 4 步相同。它不能把两组连起来，也不改变那一组的外观原型。

**拿不准就不接。** 两段不像、旁边有差不多像的竞争者、两段同时出现过、队别不同、或者是裁判，都不接。所以方法出错时多半是“当成新人”，而不是“认成别人”。

整个方法只有两个可调的设置：门槛（要多有把握才接），以及挂不挂碎片。

## 4. 三个档位

| 档位 | 冻结设置 | 事先定的上限（137 次里最多认错几次） |
|---|---|---|
| 稳妥档（strict） | 门槛 0.60，不挂碎片 | 4 |
| 均衡档（balanced） | 门槛 0.40，不挂碎片 | 7 |
| 多认档（recall） | 门槛 0.20，挂碎片 | 14 |

“冻结设置”是用规则 B 在全部 13 段上选出来的（见第 6 节），记录在 [params_loco.json](../method/reid_lab/work/fuse_r1/params_loco.json) 的 `all13` 里。

## 5. 哪些数是拟合出来的，从哪儿来

所有拟合都只用了 13 段 SN-GSR 片段和它们的标注。拟合出的数很少：

| 部件 | 拟合了什么 | 个数 | 每一折的值（留一段不看） | 全部 13 段上的值（冻结） | 由哪个脚本写出 |
|---|---|---|---|---|---|
| 切开 | 逻辑回归：前后外观相似度、和别的片段比的优势、间隔帧数、球场上的距离 | 4 个权重 + 1 个偏置 | [m_cuts/loco_params.json](../method/reid_lab/work/m_cuts/loco_params.json) | [m_cuts/final_params.json](../method/reid_lab/work/m_cuts/final_params.json) | `m_cuts/make_methods.py` |
| 位置 | 位置配对模型：距离随时间的放宽、7 个配对权重、“之前没人 / 之后没人”的各 3 个权重 | 16 | [m_space/params_loco.json](../method/reid_lab/work/m_space/params_loco.json)；合成时用的是 [params_cache/excl_*.json](../method/reid_lab/work/m_space/params_cache/) | [m_space/params_all13.json](../method/reid_lab/work/m_space/params_all13.json) | `m_space/run_position_linker.py`、`m_space/posscore.py` |
| 合成 | 配对模型：外观、位置、插件拼接各一个权重 | 3 个权重 + 1 个偏置 | [fuse_r1/params_loco.json](../method/reid_lab/work/fuse_r1/params_loco.json) 里各段的条目 | 同一文件的 `all13` | `fuse_r1/fit_loco.py` |
| 合成 | 每个档位的门槛和挂不挂碎片 | 每档 2 个设置 | 同上，各段条目的 `choice` | 同上，`all13.choice` | `fuse_r1/fit_loco.py`（规则在 `rules.py`） |
| 外观 | 最终流程里不拟合 | 0 | - | - | - |

冻结值举例：切开模型的权重（输入已标准化）是外观相似度 -1.36、优势 -0.67、间隔 +0.32、距离 +0.30、偏置 -3.34；合成配对模型的权重是外观 7.18、位置 0.65、插件拼接 -0.11、偏置 -7.18。

**没有拟合、按判断定下的常数**（敏感性分析见 [sensitivity_heldout.md](../method/reid_lab/work/fuse_r1/out/sensitivity_heldout.md)）：

| 常数 | 值 | 说明 |
|---|---|---|
| 切开的概率 | 0.7 | 是一个工作点，不是拟合值。0.9 / 0.5 / 0.3 的结果见 [m_cuts/results.md](../method/reid_lab/work/m_cuts/results.md) |
| 可靠片段的最少框数 | 5 | 沿用打分工具里“至少 5 个匹配框才算认得出身份”的常数 |
| 外观相似度下限 | 0.3 | |
| “谁都不是”的分数 | 0.5 | |
| 外观白化的收缩系数 | 0.3 | |
| 可达范围 | 8 米/秒，另加 3 米余量 | 位置部件用 |

另外，在负责人的跟踪设置上用同样流程重新拟合得到的一套参数，放在 [results/leadcfg-settings/refit_R/](../results/leadcfg-settings/refit_R/)。它选出的门槛严得多，见 [结果汇总.md](结果汇总.md) 第 4 节。

所有这些参数都只在 SN-GSR 片段上拟合，使用限制见 [许可与数据.md](许可与数据.md)。

## 6. 事先写下的规则 B

选门槛的规则在跑任何一次 `fuse_r1` 之前就写进了 [PREREG.txt](../method/reid_lab/work/fuse_r1/PREREG.txt)（2026-11-15 07:28，美国中部时间），代码在 [rules.py](../method/reid_lab/work/fuse_r1/rules.py)。

候选设置：挂碎片与否 × 16 个门槛（0.10 到 1.20）。对每个档位，在用来拟合的那 12 段上：

1. **硬上限。** 候选门槛以及所有比它更严的门槛，认成别人的次数都不能超过 `K × 这 12 段能打分的回来次数 / 137`（向下取整）。K 是稳妥档 4、均衡档 7、多认档 14。
2. **在满足上限的候选里选 J 最大的。** `J = 认对次数 − lam ×（认成别人的次数 + 被判为错的拼接数 + 可疑的碎片拼接数）`，对拟合用的片段求和，但去掉出错最多的那一段。lam 是稳妥档 10、均衡档 3、多认档 1。
3. **打平时**选更严的门槛，再打平就选不挂碎片。

如果没有候选满足上限，就先选认错最少的。

为什么这么定：上限是档位的定义；lam 防止“正好这 12 段很干净”的那一折选到最松的门槛；算 J 时去掉最差的一段，是为了不让一段片段决定所有片段的门槛（上限那一条仍然把每一段都算进去）。

要如实说明的一点：规则 B 是在 `fuse_r1` 出任何结果之前定的，但定的时候已经知道第一轮（`fuse`）的留出成绩。所以它是“事先固定”的规则，不是“盲”的规则。换一条规则，三个档位的成绩会变，见 [结果汇总.md](结果汇总.md) 第 3 节和 [局限.md](局限.md) 第 4 节。

## 7. 留一段不看（LOCO）

评估方式是留一段不看：13 段轮流当“考题”，一共 13 折。对被留出的那一段 c，所有拟合出来的东西都没见过 c：

| 东西 | 来自 |
|---|---|
| 切开模型的权重 | 用另外 12 段拟合（`m_cuts/loco_params.json` 里 c 的条目） |
| 位置模型的权重 | 用另外 12 段拟合（`m_space/params_cache/excl_<c>.json`） |
| 合成配对模型 | 用另外 12 段拟合 |
| 每个档位的门槛和挂不挂碎片 | 用规则 B 在另外 12 段上选 |

然后原封不动用在 c 上，13 段的结果加起来。`fit_loco.py` 把每一折分成四个阶段，方便检查标注用在了哪里：A 算证据表（不读标注），B 拟合（只读那 12 段的标注），C 给全部 13 段出拼接（不读标注），D 打分（被留出片段的标注只在这里用）。

文件名里的三种口径：

| 文件 | 口径 | 怎么读 |
|---|---|---|
| `METHOD_strict.json`、`METHOD_balanced.json`、`METHOD_recall.json` | **完全留出** | 门槛和权重都没见过这一段。这是主成绩。 |
| `METHOD_fixed_*.json` | **门槛冻结** | 门槛是在全部 13 段上选的冻结值，权重仍然没见过这一段。说明“冻结的门槛本身表现如何”，但门槛的选择用到了全部 13 段。 |
| `METHOD_frozen_*.json` | **样本内** | 门槛和权重都用全部 13 段。这就是交给产品版的那套参数在这 13 段上的成绩，偏乐观。 |
| `METHOD_cuts_only.json` | 只切不拼 | 拼接这一步的对照。 |

留一段不看保护的是拟合出来的数，保护不了“设计”：分长短、5 个框的界限、规则 B 本身，都是看着这 13 段定的。另有两点没有做到：切开和位置两个模型在每一折里对那 12 段来说是样本内的（没有做双重留出）；同一场比赛的其他片段仍然在拟合用的 12 段里。详见 [局限.md](局限.md)。

哪些代码读标注：

- 不读标注：`data.py`，以及应用路径 `fuse_r1/{prep,evidence,linker,linker2,method,pairmodel（apply 部分）,selfcheck}.py`、`m_cuts/features.py`、`m_appear/{core,features,agglo}.py`、`m_space/{geom,features,linker（apply 部分）}.py`。`fuse_r1/check_labelfree.py` 用审计钩子核对应用路径没有打开任何标注文件。
- 读标注：`score.py`、各部件的拟合脚本（`fit_loco.py`、`m_cuts/truth.py`、`m_space/labels.py` 和 `fitdata.py`、`fuse_r1/fuse_labels.py`）、所有诊断脚本（`diag_*`、`oracle_*`）。

## 8. 和 gbf.relink 的关系

| | 实验台（这个文件夹） | 产品版 `gbf.relink` |
|---|---|---|
| 位置 | `reid-lab/` | gbf 仓库 `src/gbf/relink/`，fork 的 `relink` 分支（提交 9a70f90 稳妥档、22754d8 多认档） |
| 作用 | 拟合、留一段不看的评估、诊断 | 只做“应用”：给一段新视频切开和拼接 |
| 参数 | 每一折一套，加上 `all13` 一套 | 只带 `all13` 那一套（冻结） |
| 档位 | 稳妥、均衡、多认 | `--relink strict`（稳妥）、`--relink recall`（多认）；不加就是关闭。没有均衡档 |
| 能处理的片段 | 只有 13 段开发片段（`data.py` 写死了名单） | 任意片段；按镜头分开处理，不跨镜头拼接 |
| 是否读标注 | 拟合和打分时读 | 从不读 |

对应关系：

- `gbf.relink` 是 `fuse_r1` 冻结方法的移植。给同样的轨迹表、标定和外观向量，它的切开位置和拼接结果与实验台一致。移植时在 13 段 × 两套跟踪设置 × 两个档位共 52 组上核对过，全部一致。
- 模块对应：`gbf.relink.cuts` ↔ `m_cuts/features.py`；`gbf.relink.appear` ↔ `m_appear`；`gbf.relink.space` ↔ `m_space`；`gbf.relink.link` ↔ `fuse_r1/linker.py` 和 `linker2.py` 的第一阶段；`gbf.relink.leaves` ↔ `linker2.py` 的第二阶段；`gbf.relink.api` ↔ `fuse_r1/method.py`。
- 产品版在这 13 段上的成绩，等于这里“样本内”那一行（`METHOD_frozen_strict.json`、`METHOD_frozen_recall.json`），因为参数就是在这 13 段上拟合的。没见过片段时的成绩要看“完全留出”那一行。
- 实验台本身不导入 `gbf.relink`。它只用 gbf 的几个基础模块（`gbf.evaluate`、`gbf.geometry` 等），所以运行实验台需要一个装好 gbf 的 Python 环境。
- 想改方法或重新拟合，在实验台里做；改完要把新的冻结参数和代码改动同步到 `gbf.relink`，并重新做一致性核对。
