# 文件清单

每个文件夹装了什么，哪些东西没有带上、为什么。逐个文件的清单（路径、字节数、sha256）在 [results/inventory.csv](../results/inventory.csv)，没带上的文件清单在 [left-out.csv](left-out.csv)。

## 1. 总览

```
reid-lab/
  README.md  README_en.md        说明（中文 / 英文）
  relocate.py                    改路径的工具（只用标准库）
  relocate.example.json          relocate.py 的配置文件示例
  manifest-sha256.txt            每个文件的 sha256
  .gitignore                     不要提交的东西：缓存、relocate 的日志、生成的副本
  docs/                          中文文档和两份清单
  method/reid_lab/               实验台本体
    data.py  score.py  check_score.py  __init__.py
    work/m_cuts/  work/m_appear/  work/m_space/  work/fuse_r1/
  pipeline/                      生成输入的脚本
    gsr/  analysis/  patches/  leadcfg/  selection.json  以及 10 个脚本
  evidence/                      历史和核对材料，11 个文件夹
  results/                       负责人设置的结果、汇总表、逐文件清单
```

## 2. method/：实验台本体

`method/` 就是原来存放 `reid_lab/` 的那个文件夹，代码里的 `sys.path.insert(...)` 指向它。`reid_lab/work/` 下每个部件一个文件夹，内部结构和原来完全一样。

| 位置 | 内容 | 规模 |
|---|---|---|
| `reid_lab/data.py` | 读一段片段的跟踪结果、外观向量、标定。不读标注。方法只允许导入它。 | 4 个文件，20 KB（四个文件合计） |
| `reid_lab/score.py` | 读标注并打分。命令行用法：`python -I score.py METHOD.json [OUT.json]`。 | |
| `reid_lab/check_score.py` | 核对 `score.py` 和输入流程自己的检查在 13 段上完全一致。 | |
| `reid_lab/work/m_cuts/` | 切开：找出轨迹中途换人的地方。代码、拟合参数（`final_params.json`、`loco_params.json`、`cutlink_params.json`）、结果表、每折的方法文件 `methods/`、日志 `logs/`、早期探索 `exploration/`。 | 101 个文件，654 KB |
| `reid_lab/work/m_appear/` | 外观：原型、按队居中、白化、聚合。代码、结果 `out/`、各次试验的输出（`exp*.out`、`diag_*.out`）。 | 111 个文件，410 KB |
| `reid_lab/work/m_space/` | 位置：后一段是不是前一段的人跑得到的地方。代码、拟合参数（`params_all13.json`、`params_loco.json`、`params_cache/`）、取舍表、方法文件和打分文件。 | 72 个文件，323 KB |
| `reid_lab/work/fuse_r1/` | 最终方法。代码、`PREREG.txt`、`params_loco.json`、10 个 `METHOD_*.json` 和 10 个 `OUT_*.json`、分析输出 `out/`、日志 `logs/`。 | 75 个文件，1.4 MB |

`METHOD_*.json` 是方法的输出：每段片段一组切开位置和拼接对，用的是跟踪器的片段编号，不含标注。`OUT_*.json` 是打分结果：13 段合计和逐段的次数。

## 4. evidence/：历史和核对材料

每个文件夹对应原来 `reid_lab/work/` 下的一个同名文件夹，内部结构不变。它们不是方法的一部分，最终方法不导入其中任何代码（唯一的例外是可选检查 `fuse_r1/check_r0.py`，它读 `evidence/fuse`）。

| 文件夹 | 是什么 | 规模 |
|---|---|---|
| `fuse/` | 第一轮合成（没有分长短）。被 `fuse_r1` 取代，留作对照。 | 58 个文件，480 KB |
| `m_keep/` | 试过但最终没用的部件：判断插件自己的拼接该保留还是该断开。 | 143 个文件，602 KB |
| `diag_cues/` | 诊断：队别、位置、相机、球衣号、外观这些线索各自有多少信息量。 | 73 个文件，363 KB |
| `diag_failures/` | 诊断：167 次回来为什么认不出，理想情况下的上限是多少。 | 58 个文件，235 KB |
| `critic/` | 批评者：方法还缺什么（按比赛分开看、去掉位置、球衣号的理想上限、封闭名单等）。 | 28 个文件，110 KB |
| `v_leak_0/`、`v_leak_1/` | 检查员“偷看检查”两轮：留出的片段有没有影响到自己的成绩，成绩有多少依赖于看着 13 段做的选择。 | 147 个文件，947 KB；52 个文件，352 KB |
| `v_repro_0/`、`v_repro_1/` | 检查员“复现检查”两轮：从空缓存重跑是否逐字节一致；不用打分工具手算是否一致。 | 79 个文件，498 KB；118 个文件，1.0 MB |
| `v_robust_0/`、`v_robust_1/` | 检查员“稳健性检查”两轮：逐段、重抽样、敏感性、各种保险规则、换规则。 | 44 个文件，428 KB；56 个文件，646 KB |

第 0 轮检查的是 `fuse`，第 1 轮检查的是 `fuse_r1`。每个文件夹的 `README.md` 是当时的英文报告。

## 6. 没带上的东西和原因

| 类别 | 文件数 | 大小 | 原因 |
|---|---|---|---|
| 二进制的中间结果（pkl、parquet） | 19 | 19.01 MB | 运行数据，可以重新生成 |
| 逐条明细表（CSV / JSON），按计划排除 | 84 | 10.37 MB | 一行一个回来、片段、配对、拼接或帧，或带标注编号 |
| 文件快照清单（tsv） | 4 | 0.59 MB | 只有时间戳和原机器的路径 |
| 逐条列出标注人物、回来或拼接的文本和日志，打包复查时排除 | 49 | 0.50 MB | 明细表的文字版 |
| 逐条明细表和用标注生成的方法文件（CSV / JSON），打包复查时排除 | 11 | 0.28 MB | 计划的规则没覆盖到，内容同样是标注的摘录 |
| HTML 页面（各部件的可视化报告、看片页） | 4 | 0.09 MB | 按要求，这次交付不带任何 HTML |
| 早期的诊断脚本（`analysis/` 下另外 7 个） | 7 | 0.03 MB | 运行手册用不到；计划里列为可选，这次没带 |
| 和这条流程无关的工具脚本（下载、球衣识别、队别重标） | 6 | 0.02 MB | 不在“SN-GSR 片段 → 实验台输入”这条路上 |
| 负责人设置的实验台副本里的代码 | 5 | 0.02 MB | 和 `method/` 里的相同，只是路径不同；用 `relocate.py make-lab` 生成 |
| 缓存和重复的文件夹（`cache*/`、`__pycache__`、检查员留下的代码副本） | 2374 | 1.76 GB | 中间结果；重复的代码在 `method/` 里已经有了 |
| 运行数据（两套跟踪设置下各段的视频、parquet、npz、pklz 等） | - | 约 1.5 GB | 不随包带；用 `pipeline/` 重新生成 |
| SN-GSR 数据和标注文件 | - | - | 数据集的使用规则不允许提交 |

说明：

- **明细表为什么不带。** SN-GSR-2025 在项目的数据登记里是“不可提交，只发数字，不发画面”。一行一个回来、一个片段、一对拼接的表，带着标注里的人物编号、球衣号、离开和回来的帧号，等于标注的摘录。汇总数字（按片段、按分档、按曲线）不受这个限制，都带了。
- **判断标准。** CSV 和 JSON：表头或键里有标注编号一类的列，或者按片段展开超过 16 行的逐条表，不带。文本和日志：有 4 行以上点名某个标注人物或某一次回来的，或者是逐条表的打印输出，不带。用标注生成的“理想拼接”方法文件（`METHOD_oracle_O1` 到 `O6`）不带。
- **仍然带了的。** 各 `README.md` 是当时的报告，里面有少量句子提到具体的标注编号（例如某一段里哪几个人被认错）。它们是说明文字，原样保留了；涉及的文件列在 [packaging-changes.json](packaging-changes.json) 的 `kept_but_note` 里。如果仓库的规则更严，这几处可以再删。
- **都能重新生成。** 没带的明细表和日志，都是包里的脚本写出来的；有了运行结果和标注，重跑对应脚本就有。
- **缓存。** `cache/`、`cache_stress/`、`cache_audit/`、`*.pkl`、`__pycache__` 是中间结果，重跑会自动生成。
- **负责人设置的实验台副本。** 它的代码和 `method/` 里的完全相同，只是路径不同，所以不带第二份，用 `python relocate.py make-lab` 生成。
- **负责人的私有片段。** 不在这次交付里；包里没有由它得出的任何数据。

逐个文件的清单和每个文件不带的原因：[left-out.csv](left-out.csv)（`decided_by` 一列写明是按计划排除的，还是打包时复查排除的）。

## 8. 原来的位置和包里的位置

| 原机器上 | 包里 |
|---|---|
| `…/plugins/tools/reid_lab/{data,score,check_score}.py` | `method/reid_lab/` |
| `…/plugins/tools/reid_lab/work/{m_cuts,m_appear,m_space,fuse_r1}` | `method/reid_lab/work/` 下同名 |
| `…/plugins/tools/reid_lab/work/` 下其余 11 个文件夹 | `evidence/` 下同名 |
| `…/plugins/tools/gsr/`、`…/tools/analysis/`、`…/tools/*.py`、`…/tools/*.sh` | `pipeline/` 下同名 |
| `…/plugins/patches/` | `pipeline/patches/` |
| `…/plugins/tools_leadcfg/reid_lab/run_leadcfg_eval.sh` | `pipeline/leadcfg/` |
| `…/plugins/tools_leadcfg/reid_lab/{out_T,out_R,eval-logs,validation}` | `results/leadcfg-settings/` 下同名 |
| `…/plugins/tools_leadcfg/reid_lab/work/` 里重新拟合的参数 | `results/leadcfg-settings/refit_R/` |

`relocate.py` 知道这个对应关系：原来指向历史文件夹的路径会改到 `evidence/` 下，指向四个部件的会改到 `method/` 下，指向输入流程脚本的会改到 `pipeline/` 下。原来的完整路径写在 `relocate.py` 的 `ORIGINAL` 表里，`python relocate.py --show` 可以打印出来。

## 9. 校验

- `manifest-sha256.txt`：包里每个文件（除它自己）的 sha256，格式和 `sha256sum` 的输出一样。在没改过路径的包上可以用 `sha256sum -c manifest-sha256.txt`；改过路径之后用 `python relocate.py --verify-manifest`。
- 仓库的 `.gitattributes` 把文本文件统一成 LF，包里的文本文件已经是 LF，所以提交前后哈希不变。
- `pipeline/patches/*.patch` 的 sha256 和 `provenance-gsr*.json` 里登记的一致。
